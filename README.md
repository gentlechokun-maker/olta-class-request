# 올타과학 수업 상담 · 반 개설 요청

GitHub Pages의 학부모 화면과 Google Apps Script의 비공개 운영 저장소로 구성됩니다. 정원 6명, 상담 후 시간표 확인, 새 반 희망 원생 3명 기준을 적용합니다.

**현재 기본 설정은 명시적으로 표시되는 예시 화면입니다. 실제 시간표·신청 저장소를 연결하기 전에는 신청을 받지 않습니다.** 예시 반과 인원은 원본 시간표에서 가져온 데이터가 아닙니다.

## 구성

- `public/`: 학부모용 반 조회, 학년·요일 필터, 기존 반 상담, 새 반 개설 요청
- `apps-script/`: 비공개 Google 운영 시트에 붙이는 서버와 관리자 화면
- `tests/`: 정원·색상·중복 신청·관리자 권한·확정 검증
- `.github/workflows/pages.yml`: 테스트 후 GitHub Pages 자동 배포

의존 패키지 없이 Node.js 20 이상에서 실행합니다.

```sh
node --test tests/*.test.mjs
node scripts/build.mjs
node scripts/serve.mjs
```

미리보기: `http://127.0.0.1:4173`. `npm`이 설치된 환경은 `npm test`, `npm run build`, `npm run dev`도 가능합니다.

## 운영 규칙

| 글자색 | 상태 | 정원 |
|---|---|---|
| 검정 | 확정 등록 | 차감 |
| 빨강 | 임시 휴원 | 차감 안 함. 연락 기록 유지 |
| 파랑 | 보강 | 날짜를 지정해 해당 날짜에만 계산 |
| 녹색 | 상담 요청 | 차감 안 함 |
| 보라 | 시작 예정 | 차감 |

셀 배경색은 학생 상태 판독에 사용하지 않습니다. 담당 선생님 표시는 반설정의 `teacher`와 가독성 좋은 연한 `teacherColor`로 관리합니다. 원본 시간표 배경색은 변경하지 않습니다.

정규 잔여석은 `6 - 검정 - 보라`. 상담 신청은 자리 확보가 아닙니다. 동명이인·중복 이름, 알 수 없는 색, 메모, 정원 초과, 동일 교실의 수업 중복을 발견하면 자동 추정하지 않고 해당 반을 확인 중으로 표시합니다. 마지막 성공 동기화가 15분을 넘으면 기존 반 신청과 새 반 요청을 중지합니다.

대상은 초1~초6, 중1~중3, 고1입니다. **모든 반은 같은 학년으로만 구성합니다.** 초1·초2 모두 빅뱅 수업이지만 반과 개설 수요는 분리합니다. 반설정 grade와 빈시간 grades에는 수업명이 아닌 초1, 초2 등의 학년을 입력하세요. 고2·고3 신청은 서버에서도 거부합니다.

정규 등록을 마친 사람은 관리자 화면에서 **시간표 확인**으로 신청과 연결합니다. 연결 직전에 원본을 다시 읽으며 검정·보라만 허용합니다. 휴원 또는 이름 삭제 등 이후 변경은 ‘시간표 재확인’으로 바뀝니다. 반이 달라지거나 동명이인이면 관리자가 실제 상담 내용으로 확인해야 합니다.

새 반 개설 수요는 `학년 + 빈시간 ID`별로 집계합니다. 같은 원생 이름·정규화한 연락처의 중복은 한 명으로 계산하며, 취소·확정된 요청은 모집 인원에서 제외합니다. 3명 이상은 **검토 대상**이지 자동 개설이 아닙니다.

## 학년별 수업 편성

| 학년 | 수업 | 구성 |
|---|---|---|
| 초1 / 초2 (학년별 별도 반) | 빅뱅 | 주 1회 1시간 |
| 초3 | 아톰 1 | 주 1회 1시간 |
| 초4 | 아톰 2 | 주 1회 1시간 |
| 초5 | 퀀텀 1 | 주 1회 1시간 |
| 초6 | 퀀텀 2 | 실험 1시간 + 이론 1시간 |
| 중1 / 중2 1학기 | 니들 | 이론 주 1회 2시간 |
| 중2 2학기 / 중3 (토요일 제외) | 스레드 | 이론 주 1회 3시간 |
| 중3 토요일 | 통합과학 | 주 1회 2시간 |

반 이름은 위 기준으로 표시됩니다. 반설정의 시간 길이가 수업 기준과 다르면 검토 대상으로 표시하고, 빈시간은 수업 길이에 맞는 학년만 접수합니다. 고1 수업명·시간은 별도 지정 전까지 기존 반설정을 사용합니다. 공개 학부모 화면에는 휴원 관련 안내를 표시하지 않습니다.

## 1. 비공개 Google 운영 저장소

원본 시간표가 공개되어 있어도 **신청 저장소는 반드시 별도 비공개 스프레드시트**여야 합니다. 원본 시간표에 아래 서버를 바인딩하지 마세요.

1. 소유자 Google 계정으로 새 비공개 스프레드시트를 만듭니다. 이름 예: `올타과학 상담 운영`.
2. 확장 프로그램 → Apps Script에서 `apps-script/Code.gs`, `Domain.gs`, `Admin.html`을 각각 같은 이름의 파일로 추가합니다. `Domain.gs`는 `node scripts/build.mjs`로 생성됩니다.
3. 프로젝트 설정에서 매니페스트 표시를 켜고 `appsscript.json`을 적용합니다.
4. 스크립트 편집기에서 `setup` 함수를 실행하고 Google 접근 권한을 승인합니다. 원본 읽기와 운영 문서 쓰기에 스프레드시트 권한, 관리자 확인에 이메일 권한, 예약 실행에 트리거 권한을 사용합니다. 코드는 Drive 파일 전체를 검색하지 않습니다. 다만 여러 문서를 여는 Apps Script 특성상 OAuth 시트 범위는 한 문서에 한정되지 않습니다.
5. 프로젝트 설정 → 스크립트 속성에 아래 값을 입력합니다. 이메일·문서 ID는 공개 `config.js`에 입력하지 않습니다.

| 속성 | 값 |
|---|---|
| `SOURCE_SPREADSHEET_ID` | 원본 시간표 URL의 `/d/` 뒤 문서 ID |
| `SOURCE_SHEET_ID` | 원본 시간표 URL의 `gid` 숫자 |
| `ADMIN_EMAILS` | 허용할 관리자 Google 이메일, 쉼표 구분. setup이 최초 계정 입력 |
| `PRIVACY_CONTACT` | 학부모에게 공개할 학원 상담·삭제 요청 연락처 |
| `SITE_URL` | 실제 GitHub Pages 주소 |
| `SEMESTER` | 학기: `1` 또는 `2`. 현재 2026년 10월은 `2` (기본값). 학기 전환 시 관리자가 변경 |
| `RETENTION_DAYS` | 상담 신청 보관 일수. 기본 90, 1~365 |

`DB_ID`는 setup이 비공개 문서 ID로 자동 설정합니다. 관리자 이메일은 운영 문서 편집 권한도 있어야 합니다. 공개 `/exec` 웹앱에서는 관리자 계정 확인이 보장되지 않으므로 관리자 작업은 **비공개 운영 시트 메뉴**에서 합니다.

## 2. 원본 시간표 연결

`반설정` 시트에 한 반당 한 행을 작성합니다. 보기용 시간표는 병합 셀·메모가 있어서 처음 한 번 반과 이름 범위의 대응표가 필요합니다. `sourceRange`에는 학생 이름만 있는 범위를 넣고, 헤더·요일·시간·수업 제목을 포함하지 마세요. 빈 이름 칸도 범위에 포함하면 신규 원생을 추가할 때 다시 범위를 수정하지 않아도 됩니다.

| 필드 | 예시 — 실제 시간표와 확인하여 교체 |
|---|---|
| id | `mon-1400-room2` (변하지 않는 고유 ID) |
| grade / title | `초3` / `과학 탐구` |
| day / start / end | `월` / `14:00` / `15:00` |
| room / teacher | `2교실` / 담당 선생님 이름 |
| teacherColor | `#e8eed8` 같은 연한 색 |
| sourceRange | `C10:C12` 같은 학생 이름 셀 범위 |
| enabled | `TRUE` |

위 예시는 작동 설명이며 실제 반 설정이 아닙니다. 첫 동기화 후 관리자 화면과 원본을 대조하고 색상과 이름 판독을 검증하세요. `색상` 시트에는 실제 HEX 글자색 → 내부 상태(`registered`, `paused`, `makeup`, `consultation`, `starting`)를 등록합니다. 미등록 색은 오류로 남습니다. 실제 시트 색상과 기본 대응표를 꼭 대조하세요.

**이름 문법:** 공백·줄바꿈·쉼표·대괄호로 구분한 한글 2~5자 이름을 지원합니다. 괄호 학교 메모는 제외합니다. 외국어 이름·기타 메모·특수 표기는 자동 확정하지 않고 관리자 검토가 필요합니다. 이름 중간의 색이 달라도 검토 대상입니다.

`빈시간` 시트에는 관리자가 강사·교실 일정을 확인한 개설 가능 시간대만 등록합니다. `id, day, start, end, room, grades, enabled`를 사용합니다. `grades`는 `초3,초4,초5`처럼 쉼표로 구분합니다. 기존 수업과 같은 교실에서 겹치면 공개하지 않습니다. 원본의 모든 빈 셀을 자동으로 신청 가능 시간으로 간주하지 않습니다.

운영 시트를 새로고침하고 **올타 상담 앱 → 시간표 동기화**, 이어서 **5분 동기화·매일 정리 설치**를 실행합니다. 트리거가 실행 제한·권한 오류로 실패하면 Apps Script 실행 기록에서 확인하세요. 연결 장애 중에는 마지막 인원을 그대로 신뢰해 신청받지 않습니다.

## 3. Google 서버 배포

1. Apps Script → 배포 → 새 배포 → 웹 앱.
2. 실행 사용자: 본인(운영자). 접근 대상: 모든 사용자(로그인하지 않은 방문자 포함). 조직 계정 정책상 제공되지 않으면 해당 관리자와 확인합니다.
3. 생성된 `https://script.google.com/macros/s/.../exec` 주소를 `public/config.js`의 `apiUrl`에 입력합니다. `/dev` 주소는 사용하지 않습니다.
4. 코드 변경 시 새 버전으로 배포를 업데이트합니다. GitHub를 수정해도 Google 서버 코드는 자동 갱신되지 않습니다.

공개 GET은 허용된 수업 메타데이터·집계 인원만 반환합니다. 학생·연락처·범위·메모는 반환하지 않습니다. 브라우저가 공개 목록을 읽는 데만 제한된 JSONP 콜백을 사용하고, 개인정보는 HTTPS POST 본문으로 서버에 전송합니다. 신청 결과는 새 창의 Google 서버 접수 페이지에서 확인합니다. `no-cors` 전송을 접수 성공으로 간주하지 않습니다.

## 4. GitHub Pages

대상 저장소: `gentlechokun-maker/olta-class-request`.

1. 소스 파일을 저장소의 기본 브랜치 `main` 또는 `master`에 업로드합니다. `.local/`, `.env`, 학생 명단, 상담 내역, Google 인증 파일은 올리지 않습니다.
2. GitHub 저장소 Settings → Pages → Build and deployment → Source에서 **GitHub Actions**를 선택합니다.
3. Actions → Verify and publish GitHub Pages → Run workflow를 실행하거나 기본 브랜치에 커밋합니다.
4. 성공한 배포에서 GitHub가 표시하는 주소를 엽니다. 기본 예상 주소는 `https://gentlechokun-maker.github.io/olta-class-request/`이며, 배포 성공 전에는 접속 가능하다고 간주하지 않습니다.
5. 모바일에서 공개 목록 → 신청 → 실제 비공개 시트 저장 → 관리자 확정 흐름을 확인한 다음 네이버 공지에 링크를 넣습니다.

비공개 저장소의 Pages 사용 가능 여부는 GitHub 요금제·조직 정책에 따라 다릅니다. 무료 공개 저장소를 사용하더라도 원생 정보는 넣지 않습니다.

## 관리자 사용

- 운영 시트 → 올타 상담 앱 → 관리 화면. 원생 연락처는 이 비공개 화면에서만 조회합니다.
- 상담 신청: 접수 → 상담 중 → 원본 시간표에 검정/보라로 등록 → 시간표 확인 → 해당 원생 본인 확인 → 확정.
- 신청 취소는 시간표를 수정하지 않습니다. 등록 자체의 취소·휴원은 원본에서 별도로 수정해야 합니다.
- 휴원: 빨간 원생을 감지하면 연락 기록을 만듭니다. 최초 감지일을 실제 휴원 시작일로 수정하고 종료 예정일·연락 예정일을 입력합니다. 종료일이 지나도 자동 복귀하지 않습니다.
- 보강: 파란 이름만으로 날짜를 알 수 없으므로 관리자 화면에서 날짜를 배정합니다. 날짜를 아직 지정하지 않은 파란 원생은 과예약을 막기 위해 모든 날짜의 보강 가능 인원 검사에서 보수적으로 차감합니다. 날짜를 배정한 뒤에는 그 날짜에만 포함합니다. 시트 파란 이름과 보강 목록은 이름 기준으로 중복 차감하지 않습니다. 일회성 결석·휴강·공휴일은 자동 추론하지 않으므로 관리자가 실제 출석을 확인해야 합니다.
- 신청 보관: 기본 90일 후 매일 정리 트리거가 상담 신청·감사·지난 보강 기록을 삭제합니다. 기간을 바꾸면 안내 문구에도 같은 값이 반영됩니다. 휴원 연락 기록과 원본 재원 명단은 별도 운영 자료로 유지하므로 불필요해진 자료는 운영자가 삭제합니다. Google 문서의 버전 기록·복사본 등은 이 정리 작업의 대상이 아닙니다.

## 검증 범위와 한계

로컬의 단위 테스트와 브라우저 미리보기는 검증할 수 있습니다. 실제 Google 권한·원본 색상·시트 API·트리거·수신 POST 동작은 소유자 계정 연결 후 실서비스 점검이 필요합니다. 서버의 동시 처리 구간은 ScriptLock으로 보호하며, 동일 요청 ID와 동일 원생의 중복 접수를 방지합니다. 전화번호 소유 확인이나 CAPTCHA는 포함하지 않습니다. 자동 악성 접수는 연락처별·전체 일일 제한으로 일부 완화하지만 공개 서비스 규모가 커지면 별도 인증·방어 기능을 추가해야 합니다.

운영 문서의 내부 표(`신청`, `동기화`, `원생`, `보강`)를 직접 수정하면 검증을 우회할 수 있습니다. 일상 처리는 관리자 화면으로 수행하고, 설정 변경 후에는 시간표를 다시 동기화하세요. 외부 원본 편집과의 완전한 원자적 동기화는 아니므로 정기 동기화 간 최대 5분 차이가 날 수 있습니다.

## 종전 보강 신청 (기존 기록 관리용)

학부모 화면의 **보강 수업 신청**에서 정규반, 실험/이론, 수업 전/후, 날짜를 선택합니다.
실험은 30분, 이론은 60분이며 정규반 바로 전후로 계산합니다. 한국 시간으로 이미 지난 시간, 정규반과 다른 요일, 오후 10시를 넘어 끝나는 보강은 서버에서도 거절합니다. 정확히 22:00 종료는 허용합니다.
정규반 만석이어도 별도 보강 상담을 접수할 수 있습니다. 원본 확인 중인 반은 신청을 중지합니다.

신청 기록은 비공개 운영 문서의 `보강신청` 탭에 저장되며 첫 접수 때 자동 생성됩니다.
관리 화면의 **보강 신청 접수**에서 재원생 본인 확인 후 실제 선생님과 교실을 반설정과 동일한 표기로 입력하여 확정합니다. 정규 수업과 다른 확정 보강의 자원 충돌 및 한 보강당 6명 제한을 검사합니다. 같은 학년·종류·시간·선생님·교실일 때만 함께 배정합니다. 근무 시간과 이동 시간은 관리자가 별도로 확인합니다.
기존 `날짜별 보강`은 정규반에 합류하는 종전 기록으로 유지됩니다. 새 보강 신청은 정규 등록으로 전환하거나 정규반 자리를 차감하지 않습니다.

업데이트 대상: `public/`과 `apps-script/Code.gs`, `Domain.gs`, `Admin.html`. 서버를 먼저 저장하고 기존 웹앱 배포를 새 버전으로 갱신하세요. 기존 문서를 초기화할 필요가 없습니다. 서버가 구버전이면 학부모 보강 신청 버튼 대신 준비 중 안내를 표시합니다.

보강은 결석한 수업 내용을 보충하는 수업입니다. 결석 날짜와 수업 내용을 필수로 받고, 내용을 모르면 확인 요청으로 입력할 수 있습니다. 관리자가 확인한 뒤에만 확정합니다. 같은 날짜·내용의 결석 수업을 보충할 때만 공동 보강 배정을 허용합니다.


## 설명회·방문 상담·연간달력 보강

새 학부모 신청 페이지는 booking.html이며 운영 방법은 [BOOKING-GUIDE.md](BOOKING-GUIDE.md)를 확인하세요. 새 보강은 초등 30분, 중·고등 60분이고 같은 수업 주차의 빈자리 반 합류와 패스를 지원합니다. 설명회 대면 20명, 온라인 무제한 및 월~목 오전 방문 상담 예약을 지원합니다.
